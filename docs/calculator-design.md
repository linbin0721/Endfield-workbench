# 325 挑战计算器

## 范围与默认值

- `/325` 是独立工具页。以常驻面板四项属性中至少一项显示 325 为目标；可指定必须同时满足的属性。
- 干员覆盖固定数据版本中可用的全部 33 个角色记录（含两种管理员外观）；默认提弗洛斯、90 级、0 潜能。等级可调，潜能可指定或搜索任意潜能。
- 同类型武器任意选择、武器满级；装备可为空，两个配件位置允许同款。支持限制装备属性词条锤炼、武器精炼及基质基础/技能词条增级。基质第二词条不改变四维属性，不作为要求。
- 当前等级下取已解锁突破、装备适配和能力节点全满，信赖满足能力节点要求。只计算常驻属性，排除食物、队友和战斗触发增益；技能伤害/攻击力增益不会误算为四维属性。
- 排序：达标属性项数降序，其次养成成本（装备锤炼次数 + 基质增级 + 武器精炼 × 10），再按潜能升序。这是展示启发式，不等于资源价格或战斗强度。

## 扩展边界

| 层 | 入口 | 责任 |
| --- | --- | --- |
| 数据 | `tools/import_calculator_data.py` | 固定版本导入、属性语义识别、来源哈希；遇新修饰类型主动失败 |
| 领域 | `web/src/calculator/types.ts` | 干员状态、装备选择、修饰项、搜索请求/响应；不依赖 React 或 API |
| 计算/校验 | `evaluate.ts` | 从原始物品与每条词条等级复算；检查穿戴、潜能、武器类型与合法范围 |
| 搜索 | `search.ts` | 有界候选生成、目标投影、折半搜索、去重与排序；可替换算法 |
| 执行 | `search.worker.ts` | 浏览器独立线程；页面取消时终止 Worker，旧结果不回流 |
| 展示 | `CalculatorPage.tsx` | 输入、限制、方案和复制；按路由延迟加载，不占 OCR 队列 |

目标值通过 `SearchRequest.target` 传入，UI 第一版固定 325。后续库存约束、不同目标、收藏与自定义养成可扩展请求或新增策略；服务端存储应放独立模块，无需把静态数值存入题号目录。规则和数据分别有 `rulesVersion`、`schemaVersion`，变更时同步导入器、校验器与基准测试。新增更复杂 modifier 阶段需显式扩展，不能静默折为加法。

## 公式和边界

当前固定数据中的四维修饰只有 baseAddition（5）与 baseMultiplier（6）；武器常驻能力百分比和装备能力百分比加到同一乘区。最终值为 `(等级原始属性 + 能力节点 + 潜能 + 武器固定值 + 装备固定值 + 常驻套装固定值) × (1 + 常驻百分比之和)`；最后向下取整，显示 325 对应原始值 `[325,326)`，不逐词条取整、不在最终显示前加容差。

`all_attr_up` 不能按键名盲目解析：布道自由的描述指主能力，负山的全能力是战斗触发效果。导入器依据无条件首句及明确映射识别。三件套常驻 +50 属性要计算，其余伤害/攻击类套装不纳入四维结果。

搜索先用小部分预算寻找不锤炼装备的基础方案，避免较慢设备只花时间建索引却无可展示结果。随后将护甲/护手与两个配件拆分，配件对按整数固定值索引，并按百分比及相关属性套装分组。依次搜四属性、三属性、双属性，再回退单属性；每档有预算，先搜索无相关百分比装备平面，再扩展百分比装备。属性贡献相同的候选合并到较低锤炼成本，所有返回结果都从原始 ID 和词条重新校验。

每次默认最多 10 秒、最多 5 个方案；配件索引每目标平面最多 120,000 项，护甲/护手对按成本分层最多 80,000 项（四属性档为 20,000）。达到预算、索引边界或展示上限时返回 `complete=false`。投影合并可能损失额外达标或不同外观方案；展示的是已找到方案中的多属性优先，不承诺全局最优或全部多解。未穷尽时零结果只能称“暂未找到”，不能称“无解”。

## 数据与验证

- 数据来源：[AKEndfield Wiki](https://www.akedata.wiki/)，版本 `1.5.3/10506507-7`，源更新时间 2026-09-24。只提交归一化数值和名称，不提交原始大表、图片或外部脚本源码；输出记录各表 SHA-256。
- 公式参考：[AKEDatabase 数值研究](https://github.com/NagiYume/AKEDatabase/blob/main/public/CH/research/终末地数据导论.md)；常驻属性语义交叉核对 [CEP 的面板计算源码](https://github.com/cmyyx/cep/blob/main/src/lib/planner/progression.ts)。独立实现，未复制其代码。
- 更新数据：`python3 tools/import_calculator_data.py --cache deploy/.local-backups/calculator-tables --download`。修改固定版本与语义后运行下列验证，审核数量/数据差异，再发布。
- 测试（Node.js 22.18+）：`cd web && npm run test:calculator`。余烬 P0 双属性、P2 三属性公开数据方案为固定基准；另覆盖合法等级、潜能累积、百分比、常驻套装、词条锤炼、武器类型与搜索限制。
- 公开数据复算不等于已在游戏内穿戴验证。版本更新、活动装备和边界显示规则仍需实际游戏对照；页面展示数据版本并提示核对。
