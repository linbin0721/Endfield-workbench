# 稀疏棋盘识别修复记录

2026-09-18。仅用原有 `balloon-empty.jpg` 和新增手机图 1、3 选择参数；手机图 2 保留给主代理独立验收。三张新增截图及旧图都是私有材料，不进入构建包。缩放、加边框是同一张原图的变体，不计为新增独立样本。

## 定位实验与决定

旧定位器以灰度阈值 130 提取明亮外框，再寻找同排至少三个连续框和至少两排的规则排列。旧图有 16 个白框，能得到 5×5；图 1 和图 3 各只有 5 个白框，前者分散，后者只占中间一排，因此均返回 `no_board`。

对调参图的灰色地块轮廓试了阈值 30、35、40、45、50、55、60、65、70。45 附近可取得包括灰格的完整或近完整规则排列：旧图、图 1 均检出 25 个对齐格，图 3 检出 22 个；排列聚类仍得出完整 5×5 尺寸和位置。30–35 有较多灰格漏检，55 以上有明显的内轮廓重复，65–70 漏掉暗格。因此固定使用阈值 45 只定位棋盘几何，再以原阈值 130 的白框与网格坐标匹配，标记 `usable`。其他格保持未知；灰格轮廓用于推断完整网格，并未仅凭白框缺席自动标记 `blocked`。这是一组有限截图的参数选择，不代表一般屏摄或其他界面亮度的最优值。

进度 OCR 使用棋盘上方中间分区；库存 OCR 使用棋盘右侧分区，范围按检测出的棋盘宽高计算，沿用原有 `(right+0.30×宽, top-0.06×高)` 至 `(right+1.55×宽, bottom+0.18×高)`。没有从原图固定像素位置裁切，也没有预填题号或题目答案。目标总升力只用于显示与核对，不补库存。

调参图上的库存圆圈数字 1 常被 OCR 读成 `V`。只在库存行的文字 OCR 明确含“升力”和数字时，才从该行文字框右端附近截取数字小分区（横向相对框右端约 `-0.515×格宽` 至 `-0.223×格宽`，纵向中心 `±0.24×格宽`）。当原圆圈裁剪未可靠读出数字时，另取圆圈中心偏左的紧裁剪；两个小分区都以至少 0.85/0.8 置信度读出同一数字才补入草稿。原圆圈与文字数字都可靠却冲突时留空并提示核对。库存标签“几级回收气球”不当作升力，因为旧图 4 级的升力为 6。旧图最下行仍因缺少可靠一致证据而留空。

## 调参集结果与边界

真实原图从识别入口返回：旧图 5×5、16 个外圈可放格、前三种库存 6×3 / 3×3 / 2×3、末行升力和数量均空、目标 36；图 1 5×5、可放格 `(1,3),(2,1),(2,2),(2,3),(3,3)`、库存 3×1 / 1×4、目标 7；图 3 5×5、可放整行 `r=2,c=0..4`、库存 2×1 / 1×1、目标 3。其余格保持未知。`test_recognition.py` 把图 1 和图 3 加入私有样本回归；缺图会明确跳过，公共坏图/限额/超时测试继续运行。

主代理独立留出图 2 的原图与加黑边变体均识别出其标注棋盘、库存和目标；75% 缩放版的棋盘与目标正确，其中一个库存升力留空待用户确认。此结果不用于回调上述参数。仍需更多独立图片才能评估不同屏幕、照片、亮度和 UI 版本的可靠性。
