# 气球题：证据与实现边界

## 样本事实

用户提供未摆放截图 `55fbdff86c67e8436f22ddb2bd0e32f7.jpg` 与已完成截图 `3e43d0f515fdac41df9239678894e99d.jpg`。题号 WL-A2012，棋盘 5×5，外圈16个可放置格。已完成布局使用升力1、2、3、6各3个，合计36。未摆放截图最下方库存数量受到界面遮挡，自动识别不得把看不清的数量伪装成直接识别值。

已完成布局，行从上到下、列从左到右；0为空，-为禁用：

```
1 1 6 3 1
0 - - - 2
3 - - - 0
6 - - - 6
0 2 3 2 0
```

以中心为原点，列坐标与行坐标分别为 -2,-1,0,1,2。该布局满足 Σ(升力×列坐标)=0 和 Σ(升力×行坐标)=0，且使用全部库存。该事实只验证样本，不能据此声称已覆盖所有玩法变体。

## 参考与待确认

公开项目 [EndBalloonPuzzle 的求解器](https://github.com/DaliBerr/EndBalloonPuzzle/blob/main/lib/solver.ts) 同样以两个方向的加权和归零作为平衡判据。仅用于核对规则，当前未确认其代码许可，不复制实现。

2026-09-17 用户明确确认：升力倍率按距棋盘中心的行、列距离分别计算，中心为0、相邻为1、外圈为2；要求左右和上下加权升力分别相等。当前 `center-torque-v1` 求解模型与该规则一致，此项不再待确认。不自行引入额外独立地块倍率。

## 截图识别方案边界

采用 OpenCV 检测格子与棋盘布局，数字交给本地 RapidOCR；不把整幅画面的所有信息都交给通用文字OCR。无可信依据的字段返回未知并要求手动校正。完整截图优先，屏摄与已摆放题面需要明确识别边界或引导重置。

主代理环境探测：rapidocr-onnxruntime 1.4.4 可离线加载其已安装模型；首次加载并识别用户完整未摆放图约4.04秒（本机单次观测，非服务器性能保证）。识别到了题号、0/36与升力标签，小库存圆圈未在整图识别中返回，需要区域放大或手动输入。主机配有 OpenCV、NumPy、Pillow、ONNX Runtime。

后续诊断：将同一原图的库存区域临时裁出（483×602）再识别，模型已加载后的单次识别约1.92秒，多返回两个数量字符“3”，仍有库存漏检。这只说明分区值得尝试；固定裁剪坐标仅用于诊断，不能直接作为适配任意图片的识别实现。

进一步诊断：中性亮色轮廓筛选能取得外圈16个近似97×97像素的完整格子轮廓，也混有界面按钮等干扰；需要按尺寸和规则排列聚类。将四个数量徽标分别裁出并放大，前三个读到“3”，最下方被遮挡的徽标却以约0.93置信度误读为“2”。因此不能只用 OCR 置信度决定是否可信，必须结合徽标完整性和库存总升力一致性，无法确认时要求用户校正。这里的坐标裁剪仍仅为人工定位诊断。

依赖来源：[RapidOCR](https://github.com/RapidAI/RapidOCR)，工程为 Apache-2.0；部署时记录所用包和模型来源。原始游戏截图仅作为私有验证材料，不默认放入网页静态目录或公开发布。
