# T04 识别与计算隔离设计

状态：2026-09-17 后端实现并通过独立验收；前端接入进行中。以 `balloon-rules.md` 的真实诊断结果为依据，验收记录见 `tasks.md`。

## 识别数据

识别返回可编辑草稿，区别于求解的严格完整题目。尺寸、地块、库存等不确定字段允许为空，并附待检查项。只有图像中存在的依据才能标记为识别结果。不得根据题号、截图哈希或预置答案直接填题目。

清晰、完整、重置后的截图优先。通过格子轮廓的尺寸和排列聚类定位棋盘，不把固定截图像素坐标作为识别器。数字采用 RapidOCR，对库存分区处理。图像变形、遮挡或已摆放气球导致无法确定时给出具体提示，并允许手动录入。

库存数量需要校验徽标是否完整、OCR 是否可靠，并与可读取的目标总升力交叉核对。不一致时标记需要校正，不能为了凑齐总升力自动补数；唯一例外是 `app/puzzles/balloon/derive.py` 的严格推导：目标总升力置信度足够、本轮无冲突、补全结果唯一且满足单项/总量与 usable 格数约束时才补入，并在 issues 中写明推导行和值，否则保持空值。只有一个样本可用时应明确识别验证范围，不能宣称覆盖所有截图和拍照。

## 时间与内存

已有进程池继续限制并发和排队数量。识别包含本地库调用，不能依靠 Python 搜索循环的协作式时间检查。建议每次识别在工作进程内启动一个单独子进程，传入有限大小的图片字节，子进程完成后返回有限大小 JSON。设置明确的识别超时；超时杀死并等待这个直接子进程退出后，才释放原任务槽位。

子进程只运行项目内的固定入口，不运行请求提供的命令，不使用 shell；不再启动其他子进程。限制 ONNX/OpenCV 线程。这个方案会重复加载模型，首版先接受该开销，以测量结果决定是否改成长驻可回收工作进程。

Python 官方 `subprocess.run(timeout=...)` 会在超时后杀死并等待子进程，但底层创建进程的耗时不一定可中断：[Python 3.11 subprocess 文档](https://docs.python.org/3.11/library/subprocess.html#subprocess.run)。实现和测试必须保留该实际边界，不宣称任意机器上毫秒级硬截止。

HTTP 上传总字节数必须在解析完整请求前受限，并限制并发上传；另外限制单文件字节数、实际图片格式、解码像素数和参与识别的分辨率。不能仅信任文件后缀或 Content-Length。临时上传文件必须关闭，原图不进入永久目录或日志。前后端大小限制需一致。

## 验收

真实原图与缩放版本均产生来自图像的草稿；确认已知16个外圈可放置格，未知库存可手动补全后求解。坏图、超大图、无棋盘和识别超时分别处理。验证超时子进程实际退出、槽位可复用。浏览器完整走通图片识别、校正、求解并保留用户输入。

## 当前本机模型来源记录

环境探测使用 `rapidocr-onnxruntime==1.4.4`，安装包元数据声明 Apache-2.0，内含 `ch_PP-OCRv4_det_infer.onnx`（4,745,517 字节）、`ch_PP-OCRv4_rec_infer.onnx`（10,857,958 字节）和 `ch_ppocr_mobile_v2.0_cls_infer.onnx`（585,532 字节）。不另复制未知模型。RapidOCR 官方说明其模型由 PaddleOCR 转换为 ONNX：[RapidOCR](https://github.com/RapidAI/RapidOCR)、[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)。后续部署记录实际安装版本及许可声明，不把本机包的可用性当成新服务器已安装。
