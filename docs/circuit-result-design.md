# 源石电路真实颜色与完成棋盘设计

状态：EW-007 冻结设计。目标是让用户直接按颜色和拼块轮廓复现答案，不再阅读通道、拼块编号或坐标。

## 产品结果

- 求解成功后的主内容只显示一个接近游戏完成状态的棋盘。
- 彩色拼块使用截图识别色相；按题号查询使用目录候选随题面保存的色板。
- 不在答案格中显示 `C1`、`P1` 等编号，不显示摆放清单、锚点、旋转角度、行列约束，也不增加“显示约束”或“查看详细坐标”开关。
- 每个库存拼块显示为连续色块。同色拼块相邻时仍有独立外轮廓；同一拼块内部格线不应让它看起来像多个独立方块。
- 障碍、固定格、空格和已放置拼块必须视觉可区分。固定格使用同通道颜色及非文字图形标记。
- 用户可见区域不依赖编号；无障碍语义的可访问名称使用颜色名称和拼块格数，不在画面增加文字清单。

## 色板契约

新增共享模型 `CircuitDisplayColor`：

- `channel`：严格整数，范围 0～3。
- `hue_degrees`：有限浮点数，范围 `[0, 360)`，采用标准色相角。

公开字段统一命名为 `display_palette: list[CircuitDisplayColor]`：

- `CircuitRecognitionResult`：`recognized` 必须携带与 `puzzle.channels` 完全一致的连续通道；其他 outcome 必须为空列表。
- `CircuitCatalogCandidate`：允许空列表以兼容已有目录行；非空时必须与候选题面的通道一一对应。
- 色板只负责展示，不进入 `CircuitPuzzle`、求解、独立校验或题面指纹。
- 视觉层现有 OpenCV hue 范围是 `[0, 180)`；跨进程前转换为 `(hue * 2) % 360`。不直接保存截图 RGB、饱和度或亮度，前端用统一饱和度和明度生成清晰颜色。

## 识别与目录

- 条形、数字、罗马和混合约束路径已经得到按题面通道排序的 `channel_hues`；识别编排应把它们随 recognized 结果带出，不能重新聚类或按题号猜色。
- `circuit_catalog_candidate` 增加非空 JSONB `display_palette`，默认 `[]`，以幂等 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 兼容生产旧表。
- 新候选保存其首次题面及对应色板。后续等价观察不能改变已有非空色板。
- 旧候选色板为空时，只有新观察的题面 JSON 与已存题面完全相等，才允许补入新色板；全局通道重编号、拼块乱序或初始方向不同但指纹相同的表示不得直接复制色板，避免颜色错配。
- 同一图片摘要的 duplicate 路径也执行上述安全补色；digest mismatch 仍不改历史。
- 目录不可用仍不得阻断截图识别和求解。旧候选没有色板时，前端使用固定回退色板。

## 前端绘制

- 防御性校验色板索引、长度和色相；任何无效或缺失值整体回退到固定的高对比色板，不能部分错配。
- 截图完整题面使用本次识别的色板；目录候选和纯题号查询使用候选自己的色板。提交求解时页面同时保存题面与色板，求解 API 本身不接收色板。
- 答案棋盘使用 SVG 或等价矢量分层：底格、障碍、固定格、每个 placement 的色块和外轮廓。轮廓按内部 `piece_index` 计算，但编号不得显示。
- 同一拼块相邻格之间连接为连续色块，只在拼块外边缘描边；不同拼块即使同色，相邻边仍可见。
- 颜色使用 `hsl(hue_degrees ...)` 派生填充、亮边和阴影；不复制游戏图片资源。
- 目录候选预览使用同一真实色板，以色块或颜色名称关联约束与库存，不再把 `C1`～`C4` 当作主要视觉标识。
- 维持答案的独立前端结构校验：题面或 placements 非法时只显示错误，不能绘制似是而非的棋盘。

## 两个实现批次

### 批次 A：后端色板、目录与契约

新增共享展示模型，把已识别 hue 带到正式结果；扩展目录模型、观察对象、内存 fake 与 PostgreSQL schema；实现安全旧数据补色；更新 API/OpenAPI 和生成 TypeScript。不得改求解器、题面指纹语义、手写前端、生产服务或生产数据库。

验收包括：条形与符号路径的通道/色相对应；模型拒绝 bool、NaN、越界、重复或题面不匹配；非 recognized 不泄露色板；JSON worker 往返；目录新写、重复、二次确认、多变体、digest mismatch、旧表迁移、精确题面安全补色与等价但不同表示不补色；真实临时 PostgreSQL 和后端全量测试；OpenAPI 与生成类型可重复。

### 批次 B：完成棋盘与页面接线

实现前端色板校验和回退；让截图、目录单/多变体和题号查询把正确色板带到答案；把 `CircuitResult` 改为无编号、无坐标清单、无约束开关的游戏风格完成棋盘，并让候选预览使用候选色板。不得改识别、求解、目录规则或部署。

验收包括：多通道、旋转、障碍、固定格、两个同色相邻拼块及缺失旧色板；画面无可见 `C1`/`P1`、坐标、旋转角度或约束开关；非法结果仍拒绝绘制；模拟 API 浏览器覆盖截图和题号单/多变体；1440×900 与 390×844 无横向溢出、键盘焦点正常；气球页面无回归；生产构建通过。

两批验收后由 Codex 运行 40 张私有源石电路回归，核对真实色相，备份生产数据库，再发布 API 和版本化静态前端并验证公网截图、题号、旧候选补色、重启与回滚点。
