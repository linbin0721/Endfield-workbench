# 首版前端流程与验收设计

目标是桌面和手机都能完成气球解题；视觉先使用简洁布局和清楚的文字，终末地风格后置。技术栈沿用 React、TypeScript、Vite，产物为 Vercel 静态页面。

## 页面顺序

1. 入口：气球解谜和一句使用说明；尚未支持的源石电路显示“后续支持”，不提供空白编辑页面。
2. 图片：选择文件，桌面支持拖放和粘贴，手机支持相册选择。展示本地预览，可重新选图、清除和裁剪。只有点击“识别图片”才上传；不具备识别能力时明确说明，并允许直接手动填写。
3. 题面：可编辑棋盘尺寸、可放置格和不同升力的库存数量。数字与输入标签始终可见；棋盘坐标和答案坐标一致，屏幕最上方始终对应第一行。不确定的识别字段需要用户补全，不默认填成零。
4. 求解：显示输入校验信息、排队和计算状态；成功后展示完整棋盘及每种气球用量。无解提示检查题面，超时允许重试或检查题面，连接失败保留输入。

## 状态与资源

- 图片选择、预览、裁剪在浏览器内完成；图片不放入 URL、日志或浏览器持久存储。
- 更换或清除图片时释放旧的预览资源；替换图片或题面后清除过时答案。
- 识别草稿、已校正题面和求解答案分别保存，防止后返回的旧请求覆盖新输入。
- 提交后使用后端任务 ID 查询状态；离开页面、替换任务或任务结束时停止轮询。取消运行中的任务时按后端真实状态显示，不立即宣称计算已停止。
- 图片直传配置的 API 地址；不得使用 Vercel 重写规则中转。前端环境变量只包含公开 API 地址，不存放秘密。
- 开发阶段可演示手动流程，但不能把未接入的识别按钮伪装为可用。加载能力列表失败时显示服务不可用，不能冒充所有功能已启用。

## 图片导入与截图入口（EW-016）

- 两条解谜路由共用同一图片输入组件。设备模式只由 UA、平台和触控能力判断：Windows、macOS、Linux 默认电脑；Android、iPhone、iPad 默认移动，包含以桌面 UA 上报的触控 iPad；窗口宽度和单独触控信号不改变模式，触屏 Windows 仍是电脑。
- 电脑在选图同一主操作区显示“截取游戏窗口”，窗口缩小不隐藏；手机和平板不渲染该按钮，主按钮使用相册文案。常用操作在移动端保持至少 44px 触控区域并允许换行，长文件名不溢出。
- 截屏在点击事件内直接调用 `getDisplayMedia`（`audio:false`，`displaySurface:"window"` 只是首选提示），由用户自行选择游戏窗口；不做自动框选、桌面助手或自动上传。首个可绘制视频帧转成 PNG 后立即停止所有 track，并沿用现有选图流程做本地预览；仍需点击“识别并求解”才上传。
- 不支持 `getDisplayMedia` 或非安全上下文的电脑显示禁用按钮，并提示改用选图、拖放或粘贴。
- 无帧、来源结束、拒绝授权、清除、更换图片、路由卸载和新的截屏尝试都会使旧尝试失效并释放资源；截屏等待可取消，取消或失败不会替换当前预览。继续保持 12 MiB / 2000 万像素限制。

## 移动端与可访问性

窄屏按图片、题面、答案纵向排列；宽屏可以分栏。常用操作有清楚的文字标签，点击区域适合触屏。禁用格、空格、气球通过文字或图案辅助区分，不只依靠颜色。棋盘控制支持键盘焦点，输入均有关联标签，状态变化可由辅助技术读取。

## T03 验收边界

生产构建通过；桌面和窄屏手动输入用户样本并得到合法解；图片选择不会发上传请求；服务离线、请求失败和未知能力状态有说明；更换题面不显示旧答案；识别未接入时显式不可用。此阶段通过仍不代表包含真实图片识别的 MVP 完成。
