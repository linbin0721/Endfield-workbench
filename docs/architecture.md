# 终末地解谜工具：架构基线

状态：2026-09-16，第一版设计。具体识别与求解能力必须以实现和样本验收为准。

## 产品范围

MVP 仅实现浮空回收（气球）的识别、校正和求解，源石电路（拼块）仅预留接口与模块注册位置。电脑粘贴或上传截图、手机选图、PS 玩家使用手机拍照，最终进入相同的图片与题目校正流程。后续添加小游戏或其他工具时复用网站导航和基础服务。

浏览器下载 Vercel 上的静态网页；图片和题目直接发送到自有服务器的 HTTPS API。Vercel 不代理上传或计算请求。前端使用 React、TypeScript、Vite；后端使用 Python、FastAPI。第一版的识别和求解均在后端，以独立模块组织。

## 数据与执行路径

1. 浏览器选图、预览、裁剪；图片不会因选中或预览而上传。
2. 用户明确开始识别后，浏览器直传图片到 API。
3. API 限制上传大小、耗时和同时上传数后提交有界任务队列。
4. 固定数量的计算进程在受限子进程中校验实际图片格式与像素数并执行识别；返回可编辑草稿。未知字段保留未知状态，不用默认值伪装识别结果。
5. 用户修正后另行提交求解。后端严格校验谜题数据并计算。
6. 浏览器显示结果、无解、超时或错误，不把搜索超时当成无解。

API 进程保持响应；CPU 工作不得直接在异步请求处理函数里运行。单机起步，API 仅一个进程管理队列，固定计算进程数；不要用多个 API worker 意外复制任务状态和模型。后续需要多实例时才引入外部队列与共享状态。

## 模块边界

- `web/`：静态客户端、图片入口、API 客户端、任务状态、各谜题的编辑和答案展示。
- `api/app/`：配置、API 路由、任务生命周期、谜题注册表。
- `api/app/puzzles/balloon/`：气球的数据结构、校验、识别和求解。`circuit/` 仅保留注册与接口约定，不提前实现完整题目模型或算法。
- `contracts/`：由后端导出的 OpenAPI；前端类型从其生成，不另维护一份接口定义。
- `docs/`：架构、任务验收记录、部署说明、样本来源和规则待确认项。

不同谜题共用任务外壳，不强制共用棋盘结构。模块通过注册表声明识别和求解是否可用，前端据此显示真实能力。源石电路在 MVP 中始终声明不可用，无需提供可交互的解谜页面。未实现的功能返回明确的未支持错误，禁止返回伪造草稿或解答。

## 接口与任务约定

前缀 `/api/v1`；初始提供健康检查、谜题能力列表、任务查询与取消。识别使用 multipart 图片，求解使用 JSON；创建任务返回 202 和随机任务 ID。任务状态为 queued/running/succeeded/failed/cancelled。错误具有稳定 code 和可展示 message。

队列容量、并行任务数、结果保留时间、最大保留任务数均有界且可配置。排队已满返回 429 与重试提示；结果过期或进程重启后查询返回 404。取消运行中任务时必须说明是否实际停止计算，不能只是修改状态就释放计算槽。识别与求解的执行时间要有限制；无法安全终止的进程不能假装已经终止。具体超时实现必须通过验收后再启用长任务。

第一版不需要账号、数据库、Redis或永久图片存储。任务 ID 相当于临时访问凭据，不提供枚举所有用户任务的接口。原图不写入日志，图片临时文件须清理。CORS 使用明确的前端域名允许列表；CORS 不是身份验证或防滥用措施。

2026-09-27 增加题号目录后，PostgreSQL 成为唯一持久化服务，但原图仍不保存。目录只保存规范化题面、候选状态和图片 SHA-256 去重值；不同识别结果保留为多个候选，不能自动覆盖。任务队列和任务结果仍在单个 API 进程内存中，因此数据库的加入不改变单 Uvicorn worker 约束。数据库只连接 Compose 内网，目录不可用时截图识别与求解继续工作。

## 验证与发布

先验证资源上限、错误路径、进程退出和跨域，再验证真实谜题样本。网页执行生产构建并做桌面与窄屏检查。部署目标为 Vercel 静态站与 Linux 后端；开发环境为 Windows，启动必须兼容 spawn。部署不等于已购买服务器或获得服务器访问权，当前阶段只准备配置与说明。

2026-09-17 用户已确认区域倍率为距棋盘中心的行、列距离，分别满足左右和上下加权升力相等；与已实现求解器一致。图片识别仍需真实样本验证，不能据一张截图宣称适配所有分辨率和屏摄。源石电路的代表性截图与规则样本待其正式进入开发范围后补充，不阻塞气球 MVP。公开仓库可用于研究；复用实现前记录其许可证，未明确许可的代码不复制。
